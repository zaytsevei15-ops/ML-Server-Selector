# ML Server Selector 1.4 — локальный редактор и сборка APK через GitHub

## Что нового в 1.4

- **Меню администратора** (Настройки → «Меню администратора»). Работает **только на этом устройстве**: без пароля, без серверных прав, другие пользователи изменений не видят.
  - Страны и города: названия RU/EN, регион, добавление новой страны (код из 2 латинских букв; существующий код отклоняется), добавление и удаление городов, скрытие и показ страны, возврат стандартных данных отдельной страны.
  - Тексты: заголовок лобби, подсказка списка стран, описание любой страны. Пользовательский текст один для RU и EN; пустое поле возвращает стандартный.
  - VPN-узлы текущего списка VPN Gate: скрыть или выделить. Выделенные идут первыми в списке страны и при автовыборе. Скрытые исчезают из списка и не выбираются для подключения. Уже работающий туннель при скрытии узла **не отключается**.
  - Полный сброс с подтверждением. Язык, тему, согласие и настройки VPN сброс не затрагивает.
- Правки хранятся без шифрования: в AsyncStorage на Android, в sessionStorage в браузере (ключ `ml-local-editor-v1`). При загрузке данные проверяются схемой. «Сохранено» показывается только после успешной записи. Адреса VPN, ключи, TLS-параметры и предупреждения безопасности редактор не меняет. Отметки узлов привязаны к ID профиля VPN Gate; при смене профиля отметка просто перестаёт применяться.
- Номера разделов теперь без нулей: `1 / Выберите страну`, `2 / …`, `3 / …`, `4 / Android VPN`.
- Город, добавленный в редакторе и сохранённый как направление, восстанавливается после перезапуска.
- Версия 1.4.0, Android `versionCode` 4.

## Сборка APK через GitHub Actions

Добавлены `.github/workflows/android-apk.yml`, профиль `github-apk` в `packages/mobile/eas.json` и `.easignore`. Workflow запускается только вручную, с явной галочкой `confirm_build`. Он прогоняет проверки и ставит APK в очередь Expo EAS (`--no-wait`). Gradle на GitHub не выполняется. Пошаговая инструкция — `GITHUB_APK_SETUP.md`: загрузка в корень репозитория, один раз Expo-проект и ключ подписи, секрет `EXPO_TOKEN`, переменная `EAS_PROJECT_ID`.

**В https://github.com/zaytsevei15-ops/MLselector ничего не загружено: доступа к репозиторию нет. Workflow не запускался, APK не собирался.** Успешный запуск workflow будет означать только постановку сборки в очередь.

## Результат (общий статус)

В код добавлены встроенный Android OpenVPN, системное разрешение, отключение и добровольное автоподключение при запуске. Интерфейс переработан в духе игрового лобби Mobile Legends: синие панели, золотая эмблема, геометрические рамки и крупное действие подключения. **Android-сборка и реальный handshake не проверены; изменение IP не подтверждено.** Браузерное превью показывает интерфейс, но не создаёт VPN-туннель.

## Пинг с телефона — новая нативная функция

Добавлен собственный Android-модуль NodePing и Expo plugin регистрации/копирования Kotlin-исходника. По кнопке «Измерить пинг» запускаются три ICMP-запроса к публичному IPv4 выбранного VPN-узла через `/system/bin/ping`, без shell и пользовательских аргументов. Замер выполняется в worker thread, ограничен 10 секундами; допускается только один одновременно. Результат: медиана реальных RTT, число ответов, потери и время. Приложение не отправляет результат в API и не сохраняет его.

Это не пинг игрового сервера и не измерение до выбранного города. Сеть/прошивка/узел могут блокировать ICMP. Отсутствие ответа не доказывает недоступность OpenVPN. При отсутствующем модуле, ошибке или отсутствии ответов вместо задержки показывается «—». С включённым VPN используется текущий системный маршрут; проверка не привязана к физической сети до туннеля. При смене узла или VPN-статуса старый результат очищается, опоздавший ответ не применяется. Автоматического фонового polling нет.

**Нативный ICMP ещё не скомпилирован и не проверен на телефоне.** Нужна новая Android-сборка через Publish; браузер и Expo Go не могут выполнять этот замер. Проверить на устройстве: три ответа/частичные потери/молчание ICMP, отсутствие системного ping, переключение узла во время замера, смену сети/VPN и корректность RTT. Тест регистрации plugin относится к Kotlin-шаблону, не к финальному MainApplication.

## Источник и обработка данных

Фиксированный HTTPS-адрес: https://www.vpngate.net/api/iphone/ . Сервер приложения получает CSV, кэширует его в памяти на 60 секунд, использует тайм-аут 15 секунд и предел ответа 5 МиБ. Перенаправления запрещены. Произвольные URL от пользователя не принимаются.

Парсер учитывает кавычки, запятые и переносы строк. Для совместимых профилей запрещены скрипты, плагины, ссылки на локальные файлы, прокси и неизвестные директивы. Публичный IPv4 и порт должны совпадать с метаданными. list и inspect не содержат сертификатов/ключей. Новый публичный profile endpoint передаёт полный профиль с встроенным ключом клиенту для нативного запуска; он не ограничен Android-клиентами. В JavaScript профиль не записывается в настройки или query cache. Plugin запрещает сохранение временного профиля движком на диск; это подтверждено проверкой исходников, не файловой системы устройства.

Это **структурная проверка**, не проверка достижимости и не handshake. При запуске сохраняется CA validation и добавляются remote-cert-tls server и точная проверка CN через verify-x509-name `<HostName>.opengw.net`. Соответствие этого имени реальному серверному сертификату пока не проверено: несовместимый узел должен завершаться ошибкой, без отключения TLS-проверок. Выборка пяти профилей содержала CA ISRG Root X1; это не доказывает идентичность или EKU серверного сертификата.

VPN Gate использует добровольческие серверы и журналирует соединения. Не заявляется анонимность, политика без логов, гарантированная страна или стабильная доступность. Во время одной проверки источник вернул 97 совместимых профилей, включая 5 RU; это меняющийся снимок, не обещание доступности России.

## Нативная интеграция и оставшиеся ограничения

С версии 1.4.0 (сборка для Windows) движок `@aliakhgar1/react-native-openvpn@1.0.0` вендорен в `packages/mobile/modules/react-native-openvpn` (1.0.0-ml.1) и исправлен под RN 0.81: non-null `ActivityEventListener`, без собственного AGP, JVM 17, codegen 0.81.5; патчи `node_modules` при сборке больше не применяются (см. NOTICE.md модуля). TurboModule Openvpn. Включён OpenVPN 2; внешние VPN-приложения не нужны по проектной архитектуре. У 12 включённых arm64-v8a/x86_64 библиотек LOAD-сегменты выровнены минимум на 16 КиБ. Это не доказательство запуска на 16-КиБ Android. Старый кандидат react-native-simple-openvpn с 4-КиБ ELF не используется.

Expo plugin добавляет две non-exported службы, BIND_VPN_SERVICE и foreground specialUse, запрещает backup/always-on и исправляет исходники библиотеки. Убраны пересылка VPN-логов в logcat, дисковый log cache и сохранение временного профиля; добавлен appcompat. Патчи идемпотентны и завершают подготовку ошибкой при несовпадении ожидаемых исходников. Полный аудит нативных журналов и памяти не выполнен.

Последовательность: согласие приложения → системное VPN-разрешение → актуальный профиль страны → команда запуска → событие движка. «Подключено» устанавливается только по native state 3, не по разрешению или результату Promise. Первая попытка ограничена 60 секундами, подтверждение отключения — 15 секундами; поздние connecting/connected после отмены требуют остановки. Автоподключение выключено по умолчанию, делает одну попытку при запуске приложения, не при перезагрузке телефона. Движок настроен на сетевой reconnect; полный lifecycle, повторный тайм-аут при смене сети и failover не проверены. Нет гарантии kill switch или отсутствия DNS/IPv6 утечек.

**Лицензирование до распространения APK:** npm-обёртка заявляет MIT, но включённые de.blinkt.openvpn исходники содержат GPLv2 с дополнительными условиями. Соответствие обязательствам полного corresponding source, уведомлениям и лицензиям JNI-зависимостей ещё не установлено. Архив проекта не является подтверждением GPL-compliance; Windows-архив включает вендорный модуль с нативными бинарниками arm64-v8a/x86_64.

## Запуск и APK

Распакуйте весь монорепозиторий; не выделяйте mobile отдельно. `bun install --frozen-lockfile` в корне. API запускается `bun run dev` (4200), мобильный клиент — `bun run dev:mobile` (4300). В `packages/mobile/app.json` параметр `extra.apiUrl` должен указывать на доступный HTTPS API вашего проекта; текущий адрес относится к превью Runable.

Новая Android-сборка создаётся через **Publish в мобильном превью** (Expo-аккаунт подключается в интерфейсе платформы) или через GitHub Actions → EAS по `GITHUB_APK_SETUP.md`. Профиль `preview` в eas.json настроен на APK. Native dependency требует новой сборки: обновление JavaScript не добавит её в старый APK или Expo Go. Облачная сборка не запускалась; компиляция Kotlin/Gradle, финальный manifest, SecureStore и физическое устройство не проверены.

Android package: `com.mlserverselector_q7m2.runable`, minSdk 28, Expo SDK 54 / RN 0.81.5. Архитектуры arm64-v8a и x86_64; 32-битные телефоны не поддерживаются этой конфигурацией. Добавлены foreground service / special-use / notification разрешения и VPN-службы. RECEIVE_BOOT_COMPLETED заблокирован. Итоговые разрешения нужно проверять по собранному manifest.
